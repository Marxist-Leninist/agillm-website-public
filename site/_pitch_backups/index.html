For everyone

A working laboratory for cheaper, more flexible language models.

A language model learns by reading text and repeatedly guessing what comes next. AGILLM is testing whether that learning can be organised more efficiently: focus the main update on a small part of the network, practise several generation styles, and teach a much smaller model from the larger model’s answers.

What is real

A 1.22B-parameter model is actively training, with its state, topology and validation signal recorded.

Why it matters

Serious model experiments may become possible with less specialised hardware and more transparent evidence.

What comes next

Standard benchmarks, controlled comparisons, safety evaluation and independent reproduction.

The research idea

Three experiments in one live training system.

These are testable engineering ideas, not magic words. Each has a measured implementation and an unresolved question.

01 / DiffusionBlocks

Concentrate the main update.

The live run divides 28 transformer layers into 14 two-layer blocks. Each main local update selects one block, followed by a small whole-model anchor.

Measured: 75,435,520 selected block parameters—7.14% of the 1,056,097,280 trainable block parameters.

Still needed: a controlled dense baseline proving end-to-end savings at equal quality.

02 / AR · SAT · NAT

Practise more than one writing rhythm.

The trainer co-trains sequential generation, grouped-token generation, and parallel-token prediction so one parent can explore a speed–quality continuum.

Measured configuration: AR, SAT and NAT objectives are active in the live trainer.

Still needed: stable public inference and benchmark comparisons for every mode.

03 / Pocket student

Teach a smaller model during the programme.

A separate 49,097,218-parameter student learns from parent outputs. It is designed for cheaper experiments and CPU-friendly deployment.

Measured: a standalone 49.1M-parameter AR export exists.

Important: it is detachable and Matryoshka-inspired, not a literal strict subset of the parent’s weights.

Current evidence

What exists—and what we are validating next.

The project pairs working systems with explicit validation targets so investors, researchers and builders can see both the asset and the roadmap.

Verified now

  • A 1,221,580,802-parameter parent model was actively training on one RTX 3090 at the snapshot time.
  • The run had processed 259.0B of a planned 400B raw tokens.
  • The main local update selects 2 of 28 transformer layers, with a small full-stack anchor.
  • Fixed-block held-out cross-entropy improved from 10.3092 to 9.1006.
  • The training system records checkpoint, topology, objective, data-provenance and validation receipts.

Next validation targets

  • Publish a standardized capability evaluation suite for the live checkpoint.
  • The current model has not been demonstrated to be frontier-competitive.
  • Run a compute-matched dense ablation for end-to-end DiffusionBlocks efficiency.
  • Stabilise and verify the detachable student’s full multi-mode standalone inference.
  • Complete independent reproduction, safety evaluation and a full data-rights audit.
